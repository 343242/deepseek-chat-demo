# Design — 用量统计模块重写

> 已获用户批准的实施方案（2026-08-17）。核心决策与理由见 prd.md 痛点一节。

## 关键事实依据

- 4+1 个 `ChatModelAdapter` 构造点即全部模型调用咽喉：`ChatServiceImpl:121`（阻塞）、`:155`（流式）、`AgentModeStrategy:226`、`IntentClassifier:233`、`RewriteClientResolver:44,61`。
- `ChatModelAdapter` 已在流式轮末汇总包注入 `DefaultUsage`（buildResponseMetadata），流式真实 usage 数据本就到位。
- userId 所有站点可得（`StrategyExecutionContext.userId` ← `UserContextProvider`）。
- MessageBus → outbox → Redis Stream → Consumer 的异步骨架健康，保留、换载荷。
- Flyway V1-V27 已跑，下一版本 V28；权限追加循 V22 先例（整权限仅绑 ADMIN）。

## 一、装配层：ChatModelAssembler（唯一组装点）

`infrastructure/llm/adapter/ChatModelAssembler`（@Component，依赖 LlmClientRegistry + UsageRecorder）：

```java
public ChatClient chatClient(Long userId, String candidateId, UsageScene scene, @Nullable String conversationId)
// 唯一一处组装：registry.get(candidateId, ChatCapable.class)
//   → new ChatModelAdapter(cap)
//   → new UsageRecordingChatModel(adapter, new UsageContext(...), recorder)
//   → ChatClient.builder(decorated).build()
```

- 每请求实例化保留（per-call 状态——计时/轮间累计/eventId——的天然归宿；真正贵的客户端缓存于 Registry）。
- `UsageScene` 枚举：CHAT / AGENT / INTENT / REWRITE。

## 二、采集层：UsageRecordingChatModel

`implements ChatModel`，包 delegate：

- `call(Prompt)`：计时 → delegate → 响应 metadata 提取 usage → 发布（成功/失败统一路径，异常时 success=false 重抛）。
- `stream(Prompt)`：`doOnNext` 只累计带真实 usage 的轮末汇总帧（多轮求和），`doFinally` 一次性发布（ON_ERROR 同样发布，success=false）。
- 一次 call/stream = 一条用量事件；Agent 多轮 = 多条。
- 暴露 `getTotalPromptTokens()/getTotalCompletionTokens()/getTotalTokens()` 供 AgentGuardrails 轮间检查（合并替代 TokenCountingChatModel）；无真实 usage 按字符数/4 估算并置 estimated=true。
- 发布器 `usage/UsageRecorder`：单 `record(...)`，`messageBus.sendAsync` + `MessageEnvelope.deduplicated(eventId=UUID)`。

## 三、传输层

`usage/UsageEventPayload`（record，Nullable Long 表未知，取消 -1 哨兵）：eventId/userId/scene/conversationId/candidateId/promptTokens/completionTokens/totalTokens/estimated/success/durationMs。
消费者订阅 `usage_event_record`，eventId SETNX 短期去重 + DB 唯一约束兜底。

## 四、存储层 V28__usage_rework.sql

- DROP TABLE token_usage（无存量用户）。
- usage_event：BIGINT GENERATED BY DEFAULT AS IDENTITY PK、event_id UUID UNIQUE、user_id NOT NULL、scene、conversation_id 可空、model_id、三个 token 列可空、estimated、success、duration_ms、created_at TIMESTAMPTZ；索引 (user_id, created_at DESC)/(created_at)/(model_id)。
- INSERT sys_permission 'usage:view:all' + ADMIN 绑定（NOT EXISTS 幂等）。
- 删除 sql/schema.sql。

## 五、查询层 com.smart.rag.usage 包

`UsageQueryService` + `UsageController`（类级 usage:view）+ 实体/Mapper(XML)/DTO，PageRequest/PagedResult 标准分页：

| 端点 | 能力 |
|---|---|
| GET /api/usage/records?scene=&model=&conversation=&page=&size= | 明细分页 |
| GET /api/usage/summary | 请求数/token 求和/平均最大时长/成功率 |
| GET /api/usage/timeline?granularity=day\|month | date_trunc 参数化+白名单，generate_series 补零 |
| GET /api/usage/stats?dim=model\|scene\|user&sort=&order= | 聚合排序（白名单+XML choose） |

- 方法级 `hasAuthority('usage:view:all')` 才可传 userId；dim=user 仅管理员。

## 六、删除清单

ChatUsageTracker、UsagePayload、TokenCountingChatModel、TokenUsage、TokenUsageMapper(+XML)、UsageService/Impl、旧 UsageController 三端点、UsageStats、TokenUsageDTO、AbstractModeStrategy.usageRecorded CAS 段、ChatServiceImpl.processResult 记录调用、sql/schema.sql。

## 七、风险与回滚

- 影响聊天/Agent 主链路（impact 预计 MEDIUM~HIGH）：装饰器仅做计时/累计/发布，发布异步无抛出，主路径语义零变更。
- 回滚 = revert 整个提交簇 + Flyway V28（无存量数据，DROP/CREATE 可逆）。
