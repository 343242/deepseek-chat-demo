# 02 · 聊天工作台线框

> **页面类型**：三栏工作台（前台核心页，IA 3.1 形态 2）
> **路由**：`/app/chat` · `/app/chat/:conversationId`
> **权限**：`chat:send`
> **前置文档**：DESIGN-SYSTEM.md v0.3.1 · INFORMATION-ARCHITECTURE.md v0.3.0
> **状态**：v0.1.0 ASCII 线框（待确认后转 HTML）

> 这是平台最复杂、最高频的页面。本线框分 6 个区块详述：整体布局 / 左栏会话列表 / 中栏消息流 / 输入区 / 右栏详情 / 状态全集。

### 2.2 单条目两层信息

```
┌────────────────────────────────┐
│ RAG 流水线测试             📌   │  ← 第1层：title（13px medium, --text-primary）
│ 12条 · 14:30              ⋮    │  ← 第2层：消息数 + 时间（11px, --text-tertiary）
└────────────────────────────────┘
```

**字段映射**（ConversationSummary）：

| 层 | 显示 | 数据来源 |
|----|------|---------|
| 标题 | `title` | ConversationSummary.title |
| 消息数 | `messageCount` | ConversationSummary.messageCount |
| 时间 | `lastMessageAt` | ConversationSummary.lastMessageAt（格式化见 DS 13.3） |
| 置顶 | `pinned` | ConversationSummary.pinned |

> v0.1.1 调整：会话条目**不再显示 modelId / 模式**。理由：① 减少视觉噪音，标题+时间已足够定位会话；② modelId（如 `qwen-plus`）对用户识别会话帮助有限；③ 与 DeepSeek/ChatGPT 的简洁条目风格一致。ConversationSummary 仍返回 modelId，前端只是不展示。

### 2.3 分组规则

| 分组 | 条件 | 排序 |
|------|------|------|
| 📌 置顶 | `pinned=true` | 始终最顶，按 lastMessageAt 降序 |
| 今天 | 今天内 | 按 lastMessageAt 降序 |
| 昨天 | 昨天 | 同上 |
| 7天内 | 本周（不含今昨） | 同上 |
| 更早 | 超过一周 | 同上 |

- 空分组不显示
- 分组标题可折叠（记忆到 localStorage）
- 置顶分组与时间分组用分隔线区分

### 2.4 hover 操作菜单（⋮）

```
┌──────────────────┐
│ 📌 取消置顶       │  ← 或"置顶"（视当前 pinned）
│ ✏️ 重命名         │
│ 📦 归档           │
│ ─────────────    │
│ 🗑️ 删除    (红)   │  ← 破坏操作，弹 ConfirmDialog
└──────────────────┘
```

对应后端 `POST /api/conversations/{id}/update`（title/pinned/status）和 `POST /api/conversations/{id}/delete`。

### 2.5 加载策略

```
首屏：GET /api/conversations?status=ACTIVE&page=1&size=50
       → 渲染置顶 + 时间分组
滚到底（前 100px）：GET ...?page=2&size=50 → 追加
最后一页：底部"加载更多"消失
```

> 后端不支持服务端搜索（仅 page/size/status），搜索框只能**前端过滤已加载列表**。

### 2.6 新建会话交互

点"+ 新建会话"：
1. 路由跳 `/app/chat`（无 conversationId）
2. 中栏显示空状态（见 §6.1）
3. **左栏不立即插入新项**——等用户发出首条消息，后端创建会话返回 conversationId 后，左栏"今天"组顶部才插入

```

│                                                  │
│  ┌─ 加载更多（顶部，历史多时显示）──────────────┐ │

│  └──────────────────────────────────────────────┘ │     前端虚拟滚动或截断渲染
│                                                  │
│  ═══ 今天 14:30 ═══                               │  ← 时间分组分隔
│                                                  │
│  [消息1 USER]                                     │
│  [消息2 ASSISTANT]                                │
│                                                  │
│  ═══ 今天 15:02 ═══   ← 间隔≥10min 才插分隔       │
│                                                  │
│  [消息3 USER]                                     │
│  [消息4 ASSISTANT · 分支 ← 1/2 →]                │
│                                                  │
│  ═══ 昨天 ═══                                     │
│  …                                               │
│                                                  │
├──────────────────────────────────────────────────┤
│ ┌─ 输入区（固定底部）────────────────────────────┐│
│ │ ...（见 §4）                                   ││
│ └────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────┘
```

### 3.2 消息视觉（无气泡）

USER 右对齐（头像在右），ASSISTANT 左对齐（头像在左，全宽排版）。

**USER 消息**：
```
                                          [👤] 你
                            帮我总结这份文档（轻气泡）
```
- 短文本加轻气泡（`--bg-base` 底，圆角 `--radius-lg` 12px，padding 8px 12px）
- 长文本也用轻气泡，最大宽度 70%

**ASSISTANT 消息**：
```
[🤖] qwen-plus · ← 1/2 →                    ← 头像 + 模型名 + 分支切换器
     ─────────────────
     这是完整宽度的回答正文（Markdown 渲染），
     支持代码块、表格、列表、公式。
     
     [代码块示例]
     ┌─ java ────────────────────────── 📋 ┐
     │ public class Example {              │
     │     ...                             │
     │ }                                   │
     └─────────────────────────────────────┘
```
- 无背景气泡，全宽排版
- Markdown 渲染（react-markdown + remark-gfm）
- 代码块带语言标签 + 复制按钮，暗色主题

### 3.3 时间分组规则

| 场景 | 处理 |
|------|------|
| 连续消息（间隔 < 10min） | 不插分隔 |
| 间隔 ≥ 10min | 插淡色分隔线 `─── 今天 14:30 ───` |
| 跨日 | 必插分隔 `─── 昨天 ───` / `─── 06-18 ───` |
| 进入会话首条 | 顶部插一条锚定起始 |

### 3.4 流式生成态（统一三模式）

⚠️ v0.3.1：三模式（SIMPLE/MULTI_TURN/AGENT）统一流式，发送后都走打字光标。

```
[👤] 你
     深度分析这份文档的技术架构
     ─────

[🤖] qwen-plus
     这份文档的技术架构主要分为▍                    ← 末尾闪烁光标
     ─────────────────────
     ● 生成中…                                       ← 底部小字 + 旋转点
```

- 光标 `▍` 蓝色闪烁（1s 周期），紧跟已生成文字末尾
- 新 token 直接追加，无逐字动画（性能优先）
- **用户上滚保护**：流式中用户手动上滚 → 暂停自动滚底，顶部浮"↓ 回到最新"按钮

### 3.5 ASSISTANT 消息完整结构（FINISHED 态）

```
[🤖] qwen-plus · ← 1/2 →                    ← 头像 + 模型 + 分支切换器
     ─────────────────
     回答正文（Markdown）…[1][2]
     
     ── 引用来源 ──                              ← 仅 RAG 模式
     [1] 📄 report.pdf · 第3页        ▸           ← ReferenceCard (DS 11.8)
     [2] 📄 manual.pdf               ▸           ← 片段正文暂不可用（待 T2 端点）
     
     🤖 Agent · 意图:深度检索(0.92) · 3轮 · 8.2s  ▸查看推理  ← 仅 AGENT 模式（DS 11.3.5）
     
     qwen-plus · ↑120 ↓80 · 1.5s · 14:31          ← 元信息行（DS 11.3.7）
     [📋复制] [🔄重生成] [✏️编辑]                   ← hover 操作栏
```

### 3.6 引用脚注（references）

**正文中的脚注**：
```
这份文档讲了六阶段流水线[1]，包括混合检索[2]…
```
- `[1]` `[2]` 渲染为蓝色上标链接（`--text-link`）
- 点击 → 展开下方"引用来源"区 + 滚动到对应卡

**引用来源区**：
```
─── 引用来源 ───
[1] 📄 report.pdf · 第3页        ▸ 查看片段（暂不可用）
[2] 📄 manual.pdf                ▸ 查看片段（暂不可用）
```
- ⚠️ Reference 当前**仅含 fileName/page/chunkId/documentId**，无片段正文
- "查看片段"按钮当前禁用（待后端补 T2 端点）
- 点文件名可跳知识库对应文档

### 3.7 分支切换器（重生成）

```
[🤖] qwen-plus · ← 1/2 →
     MMR 是 Maximal Marginal Relevance…
```
- `← 当前序号/总数 →`，仅多 children 时显示
- 切换只换这一条消息，上下文不动
- USER 消息的"重生成"按钮创建新 child 分支
- ⚠️ 后端只返回一层 children，深层需懒加载

### 3.8 hover 操作栏

```
[📋复制] [🔄重生成] [✏️编辑]
```
| 操作 | 图标 | 条件 |
|------|------|------|
| 复制 | `Copy` | 所有 ASSISTANT 消息 |
| 重生成 | `RotateCcw` | ASSISTANT（创建新分支） |
| 编辑 | `Pencil` | 仅 USER 消息（编辑后重发，创建新分支） |

## 4. 输入区（固定底部）

### 4.1 结构

```
┌─ 输入区 ──────────────────────────────────────────┐
│ [qwen-plus ▾] [RAG ●] [记忆 ●] [思考 ○]    [↻刷新] │  ← 模式开关行
│ ┌────────────────────────────────────────────────┐│
│ │                                                ││
│ │ 输入消息…（Shift+Enter 换行，Enter 发送）       ││  ← Textarea
│ │                                                ││     min-height 80px
│ │                                        120/10000││     字数计数右下角
│ └────────────────────────────────────────────────┘│
│                                          [发送 ➤] │  ← 发送按钮（右下）
└──────────────────────────────────────────────────┘
```

### 4.2 模式开关

| 开关 | 默认 | 条件约束 |
|------|------|---------|
| 模型选择器 `[model ▾]` | 上次使用的模型 | ModelSelector (DS 11.2)，按 provider 分组 |
| RAG `[RAG ○/●]` | 关 | ragEnabled，开启后检索知识库 |
| 记忆 `[记忆 ○/●]` | 关 | mode=MULTI_TURN，开启后"思考"开关可用 |
| 思考 `[思考 ○/●]` | 关 | **仅记忆模式（MULTI_TURN）可用**（ChatRequest.java:63-65），其他模式禁用 |
| 模式（隐含） | SIMPLE | 选 Agent 时输入框上方提示"Agent 模式" |

> **"记忆"即 MULTI_TURN 模式**：面向用户用"记忆"而非技术词"多轮"，语义更直觉（"开启后 AI 会记住上下文"）。开关值映射到后端 `mode=MULTI_TURN`。
>
> **无 Agent 显式开关**：模式通过模型选择器旁的下拉或独立选择器切换 SIMPLE/MULTI_TURN/AGENT。AGENT 选中后输入区显示 Agent 徽标提示。

### 4.3 关键约束

| 约束 | 值 | 来源 |
|------|----|----|
| 消息最大长度 | 10000 字符 | ChatRequest.java:28 |
| 字数计数 | `当前/10000`，超限变红 | DS 10.3 |
| **无附件功能** | 不画附件/回形针按钮 | ChatRequest 无附件字段 |
| Enter 发送 / Shift+Enter 换行 | — | 通用约定 |
| 发送按钮启用条件 | 消息非空 + 模型已选 | — |

### 4.4 发送 / 停止态

| 状态 | 按钮 |
|------|------|
| 空闲 | `[发送 ➤]`（primary） |
| 流式生成中 | `[⏹ 停止]`（secondary），点击 = 客户端 abort fetch |

> ⚠️ 后端**无停止端点**，停止只能客户端断 SSE 连接（ChatController 无 /stop）。停止后已生成内容保留。

```
└─────────────────────────────────────────────┘
```

恢复后绿色横幅"已恢复连接"显示 2s 消失。流式中断网：已生成内容保留，显示重连提示 + 手动重发按钮。

### 6.7 会话不存在（404）

直敲 `/app/chat/{无效id}` → 中栏显示"会话不存在或已删除"+ 返回新会话按钮。

### 6.8 加载态（进入会话）

中栏显示骨架屏（3-5 条消息形状灰条），加载完成淡入真实内容。

## 8. 待确认事项

| 编号 | 事项 | 影响 |
|------|------|------|
| CHAT-1 | 会话搜索是否做？ | 后端不支持服务端搜索。当前方案是前端过滤已加载列表。会话极多时只能搜已加载部分。可接受或推动后端加 keyword 参数 |
| CHAT-2 | 停止生成的体验 | 后端无停止端点，只能客户端 abort。停止后已生成内容保留，但服务端可能仍在消耗算力（直到检测到客户端断开）。体验可接受 |
| CHAT-3 | Agent 模式选择器形态 | 当前假设通过模型选择器旁的下拉切换 SIMPLE/MULTI_TURN/AGENT。也可独立成 segmented control。需定 |
| CHAT-4 | 会话标题自动生成的时机 | 后端 titleSource=SYSTEM 从首条消息截取。前端是否显示"自动"标记？建议不显示（多数产品不标） |
| CHAT-5 | 消息虚拟滚动 | 后端 /messages 不分页一次性返回。会话消息极多（上千条）时需虚拟滚动（@tanstack/react-virtual）。普通会话直接渲染 |
