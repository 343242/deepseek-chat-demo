# 04 · 团队线框（列表 + 详情）

> **页面类型**：列表页 + Tab 详情页（前台，IA 3.1 形态 2 非聊天页）
> **路由**：`/app/teams` · `/app/teams/:teamId`
> **权限**：`isAuthenticated()`（详情/成员/审批需团队成员，非成员 403）
> **前置文档**：DESIGN-SYSTEM.md v0.4.0 · INFORMATION-ARCHITECTURE.md v0.3.0
> **状态**：v0.1.1 ASCII 线框（待确认后转 HTML）

> 本篇覆盖 IA 6.2 团队列表 + IA 6.4 团队详情（成员/审批/文档 3 Tab）。团队是 RAG 协作的边界：文档归属、上传审批、成员额度都在这里管理。
>
> **v0.1.1 打磨**：① 修正与待确认事项矛盾的图示（列表行去掉文档数〔TEAM-1〕、待审批卡去掉剩余天数倒计时〔TEAM-5〕）；② 页面外壳对齐 03 篇约定（TopBar 内容、后台入口、用户位、诚实留白）；③ 补状态完备缺口（DS 2.9）：成员表"退出团队"入口、添加成员表单校验文案、表单提交中态；④ 示例人名弃用 alice/bob/carol 泛型占位，nickname 主显顺序与字段映射对齐。

### 1.2 列表项（列表卡片行，非卡片墙）

IA 6.2 定类型"卡片/列表"；按 DS 2.1 密度优先，用**横向卡片行**（全宽、单列堆叠），不用网格卡片墙：

```
┌──────────────────────────────────────────────────────────────────┐
│ 👥 RAG 平台组                                       [👑 创建者]    │  ← teamName + myRole Badge（4.4.5）
│    5 名成员 · 创建于 2026-06-20                                    │  ← memberCount · createdAt（列表 VO 无文档数，见 TEAM-1）
└──────────────────────────────────────────────────────────────────┘
```

**字段映射**（`TeamVO`）：

| 层 | 显示 | 来源 | 备注 |
|----|------|------|------|
| 团队名 | `teamName` | TeamVO.teamName | 点击进详情 |
| 我的角色 | `myRole` | TeamVO.myRole | Badge：创建者（brand）/ 管理员（success）/ 成员（neutral），复用 4.4.5 |
| 成员数 | `memberCount` | TeamVO.memberCount | |
| 文档数 | `documentCount` | ⚠️ TeamDetailVO 字段，列表 VO 无 | 列表行不显示文档数（或等后端补到 TeamVO）；当前列表行只显示"成员数 · 创建时间" |
| 创建时间 | `createdAt` | TeamVO.createdAt | DS 13.3 格式化 |

**交互**：

| 操作 | 表现 |
|------|------|
| hover | 卡片 shadow 升 `--shadow-sm`（DS 10.9），无位移 |
| 点击卡片 | 跳 `/app/teams/:teamId`（写 `ui-store.activeTeamId`，与知识库团队上下文共享，IA-3） |

**空状态**（DS 13.6）：标题"还没有团队"，描述"创建团队，与成员协作管理知识库"，按钮"创建团队"。

### 1.3 创建团队（Modal）

点"创建团队" → Modal（DS 10.11，480px）表单（react-hook-form + zod，校验对齐后端注解）：

| 字段 | label | 校验（后端） | 错误文案 |
|------|-------|-------------|---------|
| teamName | 团队名称 | `@NotBlank` + `@Size(max=128)` | "团队名称不能为空" / "团队名称最多 128 字符" |
| teamDesc | 团队描述（选填） | `@Size(max=512)` | "团队描述最多 512 字符" |

- 提交 `POST /api/teams` → 成功 Toast"团队已创建"→ 关闭 Modal，列表顶部插入新行
- 后端约束前置提示（帮助文本，非校验）：单团队最多 50 人、每人最多加入 10 个团队（`TeamProperties` 默认值）；超限后端报 `TEAM_LIMIT_EXCEEDED`（105013）/ `TEAM_NAME_DUPLICATE`（105001），按 DS 13.5 优先显示后端 message
- 创建者自动成为该团队 CREATOR 成员
- 提交中主按钮 loading + 禁用（DS 10.1 loading 态），防重复提交；成功后才关闭 Modal 并插入列表行

### 2.4 审批 Tab

双视角（IA 6.4：全员可见，审批操作仅 CREATOR/ADMIN）：

```
┌─ 审批 ───────────────────────────────────────────────────────┐
│  [待审批 (3)]   [我的审批]        ← 内层二级 Tabs              │
│                                                                │
│ ┌────────────────────────────────────────────────────────────┐│
│ │ 📄 report.pdf · 1.2 MB                                      ││
│ │ 上传者: 陈默 · 2026-08-14 14:30                             ││
│ │                              [拒绝]  [通过 ✓]                ││
│ └────────────────────────────────────────────────────────────┘│
│ ┌────────────────────────────────────────────────────────────┐│
│ │ 📄 manual.md · 45 KB                                        ││
│ │ 上传者: 高原 · 2026-08-14 10:02                             ││
│ │                              [拒绝]  [通过 ✓]                ││
│ └────────────────────────────────────────────────────────────┘│
└────────────────────────────────────────────────────────────────┘
```

**待审批**（CREATOR/ADMIN 可见，普通成员隐藏此二级 Tab；有审批权者进入审批 Tab 默认落在"待审批"，普通成员默认且仅见"我的审批"）：

- 数据：`GET /api/teams/{teamId}/approvals/pending?page=&size=`，按提交时间**先后排序**（FIFO，与"我的审批"相反），分页页码从 1 起
- 单卡 = ApprovalCard（DS 11.9 管理员视角）：文件名 + fileSize（DS 13.4）+ uploaderName + createdAt
- **通过**：ConfirmDialog 轻确认 → `POST /approvals/{approvalId}/review` `{action: "APPROVE"}`；通过后文档进入 ETL（PROCESSING → 解析/分块/向量化），卡列表移除
- **拒绝**：Modal 填 `comment`（选填，≤512）→ `{action: "REJECT"}`；按钮 destructive；确认文案 DS 13.7"拒绝此文档?"
- 重复审批后端乐观锁拦截报 `APPROVAL_ALREADY_PROCESSED`（205006）→ 前端 Toast"该审批已被处理"并刷新列表
- 帮助文本："成员上传的团队文档需管理员审批；超过 7 天未处理将自动拒绝"（`approvalTimeoutDays` 默认 7，前端不精确计算剩余天数，卡片右上仅显示提交时间；精确倒计时不做，见 TEAM-5）
- 空状态（DS 13.6）："没有待审批的文档 / 成员上传的文档会在这里等待审批"

**我的审批**（全员可见）：

- 数据：`GET /api/teams/{teamId}/approvals/mine?page=&size=`，按提交时间**倒序**（最新在前）
- 单卡 = ApprovalCard 已审批态/待审批态（DS 11.9）：fileName + status Badge（4.4.4）+ reviewComment（REJECTED 时展示，含超时自动拒绝文案"审批超时，系统自动拒绝"）+ createdAt/reviewedAt
- ⚠️ 审批人只返回 `reviewerId` 无 `reviewerName`（DS 11.9 A2 缺口），**当前不显示审批人姓名**，只显示时间与备注

### 2.5 文档 Tab

- 复用知识库文档表格（03 篇 §3，`GET /api/documents?teamId=` 数据源相同），展示团队文档与审批状态徽标（PENDING_APPROVAL / REJECTED 等 11 态，DS 4.4.1）
- Tab 内主按钮"管理文档" → 跳 `/app/knowledge/team/:teamId`（知识库团队模式，两处共享 `activeTeamId` 上下文，IA-3）；不在本 Tab 重复实现上传（避免双入口逻辑分叉）
- Tab 顶部规则说明条（仅 MEMBER 可见）：**你上传的团队文档需要管理员审批后才会进入知识库**；CREATOR/ADMIN 上传自动通过
- 额度规则（帮助文本，不上传不触发）：单成员上传总量受额度限制，超额后端报 `UPLOAD_QUOTA_EXCEEDED`（105005，"上传文件超出团队额度"）

## 3. 角色权限矩阵（操作显隐权威依据）

| 操作 | MEMBER | ADMIN（团队） | CREATOR |
|------|:------:|:----:|:----:|
| 查看团队详情/成员/我的审批/文档 | ✅ | ✅ | ✅ |
| 查看待审批 + 通过/拒绝 | ❌ | ✅ | ✅ |
| 添加成员 / 调成员额度 / 移除成员 | ❌ | ✅（不可移除 ADMIN） | ✅ |
| 改成员角色（MEMBER ⇄ ADMIN） | ❌ | ❌ | ✅ |
| 编辑团队 / 解散团队 | ❌ | ❌ | ✅ |
| 调整创建者额度 | ❌ | ❌（需系统 `team:manage` 权限 + 团队内 CREATOR/ADMIN 身份，双层校验） | ✅（同左） |
| 退出团队 | ✅ | ✅ | ❌（禁用态） |
| 上传团队文档 | 需审批 | 自动通过 | 自动通过 |

> 前端显隐仅是体验优化；后端服务层逐操作校验（`TeamMembershipVerifier`），是真正边界。矩阵中"ADMIN 不可移除 ADMIN""不可移除自己"由后端强制，前端同规则置灰/隐藏。

## 4. 状态全集

| 状态 | 表现 |
|------|------|
| 列表/详情加载 | 骨架屏（列表卡片骨架 / 页头 + Tab 骨架，DS 9.5） |

| 解散确认 | ConfirmDialog："解散团队? / 团队及所有成员、文档数据将被移除，此操作不可撤销。/ [解散]（destructive）"（DS 13.7） |

| 拒绝审批确认 | "拒绝此文档? / 上传者将收到拒绝通知。/ [确认拒绝]（destructive）" |
| 操作后反馈 | 成功 Toast 3s（DS 10.14）；失败按 DS 13.5 优先显示后端 message |
